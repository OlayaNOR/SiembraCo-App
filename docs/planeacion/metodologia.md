# Esquema metodológico

## Propuesta: híbrido

Iteraciones quincenales con backlog priorizado, combinadas con los artefactos de gestión formal que exige el cliente (cronograma, presupuesto, matriz de riesgos, actas).

**Prácticas que se adoptan:** iteraciones de 2 semanas, backlog priorizado, tablero visual, revisión y retrospectiva al cierre de cada iteración.

**Prácticas que no se adoptan:** los roles formales de Scrum (product owner, scrum master), porque el liderazgo ya rota por fase.

## Justificación

1. **El cliente exige documentación formal.** Cronograma, presupuesto y matriz de riesgos documentados: eso no lo cubre un esquema ágil puro.
2. **El caso tiene incertidumbre media-alta.** Entre sus riesgos iniciales están los cambios en normativa sanitaria y trazabilidad; eso pide ciclos cortos, no un modelo en cascada.
3. **Puede haber cambios de alcance en cualquier momento.** El cliente se reserva introducir situaciones imprevistas; hay que poder re-priorizar el backlog sin romper el plan.
4. **Las iteraciones coinciden con las mediciones.** Los dos indicadores obligatorios se miden cada dos semanas, así que el cierre de cada iteración es a la vez evidencia de seguimiento.
